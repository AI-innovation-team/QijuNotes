# 起居 · 使用说明

起居提供持久对话、每日活动、个人史、历史资料与成长记录。日期和时间采用 **Asia/Shanghai**。本指南描述源码功能；实际模型、手机通知、备份与长期运行需要在各部署分别验证。

## 打开与登录

- 在部署服务的 Linux 电脑上打开 [个人入口](http://127.0.0.1:18780)。
- 手机或其他电脑接入获授权的 Tailscale 私网后，使用部署者提供的 `http://<TAILSCALE_IP>:18780/` 地址；占位符须替换为实际主机地址。
- 仅填写 URL 不会创建 HTTPS 或公网入口；HarmonyOS 手机需要私网持续连接，后台设置见 [连接说明](HARMONYOS.md)。

新实例首次使用时，在 Linux 本机入口创建账号，填写2至64个字符的账号和至少10个字符的密码。此后电脑与手机输入同一账号密码。

勾选“在此设备保持登录30天”，可在浏览器关闭或项目服务正常重启后保持有效登录；清除站点数据、退出、改密或本机重设后需重新登录。密码可交给浏览器密码管理器保存，不发送到聊天。忘记账号或密码时按 [账号说明](ACCOUNTS.md) 在本机重设，不删除已有对话和任务。

## 聊天与图标侧栏

默认进入聊天或上次活动，通知链接优先打开指定活动。消息显示在中央，输入框在底部；电脑左侧是图标导航与最近对话列表，手机点击左上角侧栏图标展开。

界面采用蓝白配色。手机聊天正文、个人史正文和历史资料正文默认使用 17px 字号，并增加行距；输入文字也是 17px。输入框为空时只占一行，随多行或自动换行的文字增高；达到高度上限后，在输入框内部滚动，发送按钮保持可见。清空输入或收到对应发送回执后，空框恢复一行。

侧栏底部的月亮图标开启夜间护眼模式，使用柔和深色背景；太阳图标切回蓝白。选择保存在当前浏览器，刷新和下次打开会沿用；同一浏览器的其他标签页同步切换。切换保留当前对话、草稿与阅读位置。浏览器禁用本地存储时仍可本次切换，并提示无法记住选择。

侧栏图标打开今日、历史补填、随时聊聊、起居注·个人史、日程、对话原文、学习收藏、委托任务、成长主线、资料与画像及设置。图标有悬停说明和辅助名称。每日一学、睡眠打卡、每日反思分别放在三个项目文件夹里，展开后按业务日期倒序列档，可继续旧日期或打开今天；“最近对话”只列最近60项日常聊天，不混入三个例程。当前活动的继续、跳过、结束、稍后提醒、关联委托、当前记录、更正、附件与原话管理集中在侧栏，不占用消息区。

消息中的Markdown可显示标题、列表、引用、表格、行内代码和代码块，以及允许的HTTP/HTTPS链接。宽表与长代码只在各自区域横向滚动。原HTML按文字显示、不执行，远程图片不自动加载；排版只作用于聊天显示，数据库原话、导出、草稿和“对话原文”仍保留原始文字。

手机点击遮罩或关闭图标收起侧栏；键盘可使用 Escape。完整控件与恢复行为见 [聊天界面说明](CHAT_INTERFACE.md)。电脑与手机使用同一服务端记录，未发送草稿只在当前浏览器本地保留，不承诺跨设备同步。

## 问题反馈与夜间研读

在任一对话中发送“反馈：”并说明具体问题，程序会先保存原话，再立即显示“问题反馈回执”。侧栏“问题反馈”列出原对话、处理状态与实际处理结果。收到回执代表问题已记录；起居不会自行修改或部署代码，开发者修复、验证和部署后才记为已完成。聊天中明确调整长期回复偏好、每日一学要求或已有委托需求，仍通过原来的“设置处理回执”保存。

侧栏“夜间研读”显示策略、已取得材料和实际笔记。新实例默认关闭，维护者按明确要求启用后，研读窗口为北京时间 01:00—07:00。系统逐段阅读、保存原文定位与论证笔记，在下一次新课备课时选用；原课程的来源快照保持。登记来源包含毛泽东诗词、中国典籍和现代思想，按实际取得正文扩充。夜间窗口每隔30分钟检查一次可读材料；有前台会话或日常任务待处理时让行。耗尽已登记正文后显示状态，等待下一段材料，不重复计为新进展。

资料目录、原文取得和形成笔记分别显示。只有视频目录、没有字幕正文的条目不会标为已读。笔记用于备课和积累阅读进度，不表示更改了 DeepSeek 模型权重；课程中的史实、理论分析与假设例子继续分别表达。可用来源与目前缺口见[研读来源说明](STUDY_SOURCES.md)。

每日一学追问会围绕当前问题回答，承接已经发布的回复及课程修订。检查失败会显示明确状态，可按页面入口重试同一候选。历史补交或修订显示实际发布时间，并保留原课。

## 每天的三个入口

| 活动 | 默认发送时间 | 可以怎样开始 |
| --- | --- | --- |
| 睡眠打卡 A3 | 每天 08:30 | “睡得一般”，或“00:30 睡、08:10 起、3 分” |
| 每日一学 A1 | 每天 21:00 | 阅读典籍、史事与概念，再选一项追问 |
| 每日反思 A2 | 每天 21:30 | 先谈博士主线，也可直接谈科研创业、文化事业，或一次覆盖多条主线 |

每日一学会提前准备并核对材料，到点直接发布已通过检查的正文。实际生成、审核和发布时间分别保留；若未能通过检查，页面会明确显示尚未发布及原因，不把停止的任务一直显示成“正在准备”。没有模型配置或模型暂不可用时，原话仍会保存，未完成的深入回答保留待处理状态。

默认每天唤醒。没有回复、只说“收到”、回答简短或跳过本次，都不会改变明天的日程。基础记录完成、摘要整理完成和结束本轮聊天是不同状态；三类活动都能继续输入、追问和补充。

新每日一学先给一份完整短课：典籍、中国史或中共党史、现代概念。每节包含解释与示范，外国史另留一句趣闻。可以继续问“换一个例子”“这里我没理解”或直接要求答案；小练习可跳过。原日期下可一直深入，生成和已阅不会自动记成已经掌握。中国史/党史优先从持续扩充的来源目录选取未投递材料，原四组来源保留作备用；同来源复习注明原日期，旧活动内容保留。

资料页新增“资料综述”，把已导入的GPT/Kimi文件按主题串联，展开“查看依据与来源”可查原话或平台说明，也可更正、收起综述。个人史对重要本人陈述自然记载；原日期不详时保持未知，历史计划不等于已经完成或现在仍然适用。

A3 的睡眠质量可以写文字，也可以用 1–5 分，1 表示很差、5 表示很好。运动和情绪是选填。只提供睡眠感受也可以保存，未知字段不会补成零或负面值。跨午夜睡眠默认按起床日期归属。

## 发送、续聊与原生问题

在活动底部输入消息，点击上箭头“发送消息”图标，或使用 Ctrl + Enter；Mac 使用 ⌘（Meta）+ Enter。普通 Enter 换行。中文输入法正在组词时，发送快捷键会被暂时忽略，避免把选词动作当成发送；上屏后再发送即可。

界面只有在取得服务端持久回执后才显示已保存。网络断开或结果不确定时，保留草稿并使用“重试提交”图标；重试沿用同一个提交编号，不要为了重发另建一条活动。回到前台或恢复连接时页面会重新读取已保存状态，也可点连接提示中的“重新连接”；不会自动重复发送未确认的消息。已保存但模型暂时不可用时，原话仍在，处理可以稍后继续。

未发送草稿按会话保存在当前浏览器，刷新或切换会话后会恢复文字和输入框高度。发送失败时保留文字、错误提示和重试入口；自动增高不会清掉这些状态。等待回执期间继续编辑的新文字也会保留，成功回执只清除与本次提交一致的草稿。本地草稿保存失败时会显示提示，请先复制文字留存；浏览器清除站点数据后无法保证恢复草稿。

侧栏的“今天到这里”图标收束当前交流，“跳过本次”图标只作用于这次活动。之后再次进入同一日期，输入框仍然可用。

如果对话上方出现待答的原生问题：

1. 点击“回答这个问题”，把下一条消息明确关联到该问题。
2. 点击选项只会填入输入框，不会自动发送；可以编辑后补充说明。
3. 输入框上方会显示回答目标；点击“取消关联”可恢复普通讨论。

不必先完成待答问题才能继续聊天。明确回答与普通追问分别处理，不把每一条消息都当成固定问卷答案。

## 在聊天中调整长期要求

可以直接告诉起居以后怎样回应，明确说出“以后”“默认”或“保存为长期要求”，并说明适用范围。全局要求适用于各类交流；每日一学、每日反思和睡眠打卡也可分别保存专属要求，不必把同一段说明每天重发。

| 范围 | 适合调整的内容 |
| --- | --- |
| 个人全局 `global` | 回复长短、组织方式、是否先指出问题和给出建议 |
| 每日一学 `routine:A1` | 导师、教员式讲解；经典修身立德、中国史与党史分析、现代概念的解释和例子 |
| 每日反思 `routine:A2` | 军师、参谋式交流：辨明处境、关键问题与取舍，提出可实行的下一步 |
| 睡眠打卡 `routine:A3` | 枕边人、贤内助般温暖亲近的表达，结合实际睡眠、身体感受与情绪给建议；这是交流风格，不冒称真实伴侣或医生 |

例如“以后每日反思……”只调整 A2，“以后睡眠打卡……”只调整 A3。专属要求优先于全局要求；它们不把单次睡眠变成诊断，也不把建议变成已经完成的行动。要替换已有要求，说明哪一项改成什么；要停用，明确指出不再采用的那一项。指向不清楚时，起居会先问一个必要的问题。

下面三条可复制使用；第三条请先把“实际任务名称”换成看板中已经存在的任务名：

```text
以后回复请先给结论，再说明依据和可行的下一步。请保存为个人全局长期要求。
```

```text
以后每日一学先讲清概念，再给一个具体例子，最后提供可选的练习。请保存为每日一学的长期要求。
```

```text
请修改已存在的“实际任务名称”：目标改为整理报告提纲；输入限定为该任务已有材料；交付内容改为三个论点及依据；验收条件改为每个论点注明出处。保留旧成果和原验收记录。
```

想核对已经保存的要求，可发送：

```text
查看当前已保存的长期要求。
```

消息中的 **“设置处理回执”** 才说明这次设置如何处理：可能已保存并列出范围、版本和变更，也可能要求澄清或明确未执行。普通模型回复说“记住了”，以及原话已经保存的发送回执，都不等于设置已经持久生效。未拿到处理回执时，先查看该消息的状态，不必另发一条相同要求。

长期要求用于后续回复和后续活动；已经生成的课程、旧消息与原文保留。只说“这次简短些”属于本轮交流，引用他人的话、代码块或历史材料里的指令也不会自动保存为长期要求。在“资料与画像”可查看、更正或停用已保存的规则；作用域输入框提供全局和 A1–A3 建议，也保留 `project:项目名` 的填写方式。

已有任务可调整目标、输入、交付内容和验收条件。仅说“改这个任务”而无法唯一定位时，需要补充任务名；任务正在执行时会拒绝本次修改，请待本轮执行结束后重新发送。任务卡可展开“当前需求”和“需求修订记录”，**需求版本与成果版本分别计数**：修改要求不覆盖旧成果或旧验收，新成果仍需你另行验收；已取消的任务不能靠改要求重新启动。

学习专题要求目前会进入生成提示，但尚未驱动专题检索、选材和课程安排；设置回执不表示这一执行通道已经具备。

这些设置不会自动改变每日频率、暂停、任务负责人、执行权限或系统代码，也不会替你确认成果。提醒日程仍按下文的明确入口调整；用户没有明确改动时，A1–A3 保持每天唤醒。

## 补填历史日期

从侧栏打开“历史补填”图标，或点击“日常项目”标题旁的“补填历史日期”图标。近七天是初始视图，可使用日期选择器加入更早日期，也可同时选多天、逐项打开。

已有活动会打开原会话；没有活动时，仅按你所选的原日期与活动类型创建一次。补记不会取消今天的活动，也不会补发历史首次通知。

例如在历史入口输入：

```text
补记昨天的睡眠
继续 2025-01-15 的反思
补记昨天的睡眠：睡得一般；补记前天的睡眠：睡得很好
```

多日内容应为每段明确一个日期。日期含糊时，系统要求补充必要的日期，不把同一段回忆复制到多天。未确认的补记操作可点击“重试原指令”，刷新或跨午夜后仍沿用原提交编号。

活动与摘要归属原业务日期；原话另保留实际提交时间。因此今天补记昨天，在“对话原文”中保留今天的提交时间，同时指向昨天的活动；个人史若形成记载，仍归属昨天的业务日期，不会伪装成昨天已经提交。

暂停、跳过、非计划日、启用前日期和选填字段缺失都不算欠账。A1 没有讨论记录也不等于没有阅读或掌握。

## 更正记录与调整日程

A2/A3 活动侧栏的“当前记录”图标可展开摘要，铅笔“更正记录”图标用于更正。只修改确实需要更正的字段；清空一个已有字段表示明确撤回其值。更正会持续用于后续摘要，不会因新回复又被旧原文覆盖。原话与更正关系仍可追溯。

从侧栏打开“设置与运行”图标，选择相应例程的“调整日程”，可以修改时间、星期与暂停日期。**暂停包含所选截止日期，次日恢复原安排**；清空暂停日期表示取消暂停。只修改 A3 不会连带改变 A1/A2。

已实现的明确自然语言形式包括：

```text
打卡改成每周二、四
反思改到 22:00
学习暂停到 YYYY-MM-DD
打卡恢复每天
```

为避免含糊日期，暂停请使用 `YYYY-MM-DD`。活动侧栏的铃铛“稍后提醒”图标只增加一次提醒，新选择会替换尚未发送的同类提醒。“稍后提醒，明早”使用次日 08:30，并回显完整日期与时区。

## 起居注与对话原文

“起居注·个人史”由起居依据可追溯原话自动整理与你有关的经历、阅读、变化与决定，无需本人逐条批准。默认展示“已记载”，可按年份和文字查找；来源不足或尚需处理的内容显示为“待整理”，不是等待你批准。以第三人称列传式叙述，有依据的事实、当时计划和个人判断分别记述，不把助手建议、假设或未来计划写成已经发生的经历。原话引用保留原有“我”；叙述不发明姓名、称号或头衔。

个人史支持文白相间、清楚可读的第三人称列传叙事，围绕重要行动、转折和未竟之事组织篇章；有适合评述之处，可另段写“史官曰”或“赞（起居拟作）”。评述是起居的评论或拟作，不是新史实，也不冒称古人原句。调整文风时追加新版本，原稿和来源仍保留；间接整理材料与来源不足的记录保留原样，不冒作本人直接陈述。

起居会在来源充分时自动形成记载并继续编修，模型处理暂不可用时仍保留原话和可追溯的基础记载。你可随时查看出处、修改正文，或“暂不记载”；暂不记载只移出个人史，原话仍保留。本人更正优先，不被之后的自动整理覆盖。阅读仅按明确原话记载，不等于理解或掌握。来源删除会使相应派生叙述失效，具体见[个人史说明](CHRONICLE.md)。

起居担任个人史秉笔史官，使用[蓝发鱼系Q版头像](../web/qiju-avatar.png)。在“设置与运行”填写“史官在记载中如何称呼你”，未设置时默认为“用户”，可用1至32个可见字符。已有显式称谓继续保留，包括先前保存的“本人”；无需重新填写。新称谓用于自动叙述，不会偷偷改写原话或你已自行修订的正文。自动成史不代替委托成果的版本验收，也不代表整个项目已被本人接受。

“对话原文”独立保留日常交流、明确委托、三个例程与主动导入的可见原文。可按日期、全文或“原日期未知”查看，每页50条并显示总数。无原始日期的材料继续保持未知，实际导入时间另列；点击来源可回到具体原话或对象。

## 日程与提醒

从侧栏日历图标打开“日程”，选择月历、周视图或日列表。周视图显示一周 00:00—24:00 的安排，可上下滚动时间轴；手机可在周网格内横向滚动。点“＋”新建，填写名称、上海时区起止时间、可选全天、地点或会议入口、备注。提醒默认关闭，选择提前时间后才通过现有私网通知发送；锁屏正文不包含具体日程私事。

保存后仍是“计划”。到点、收到提醒和打开页面都不会自动完成；实际做完后，点勾号并确认“已完成”，个人史只记录本人确认完成的行为。取消需要明确确认，保留原计划并停止后续提醒；可勾选“显示已取消”查阅。已完成或已取消的安排不能直接改写为另一件事。

当前是单次日程，不改变 A1–A3 每日安排；周期例程仍在设置中调整。消息回执不等于手机送达，日程与活动通知需分别验证。详见 [日程说明](CALENDAR.md)。

## 收藏与附件

A1 活动侧栏的星形“收藏学习”图标保存收藏，可从导航的“学习收藏”查看。收藏、阅读和掌握是不同事实；收藏不会被自动计为能力提升。

在活动侧栏点击回形针“附件与成果”图标，选择文件，再点击“保存附件”图标；单个文件上限10 MB。附件保存后可下载，并纳入完整导出与备份。成长或资料条目出现“下载来源附件”时，可直接取得所关联原件。独立收录的报告原件与派生记录分别保存，停用画像或修改摘要不会自动删除原件。外部平台历史里的附件只有定位、没有实际文件时，会列为缺失附件，不冒充已导入文件。

## 明确委托与成果验收

从侧栏打开“委托任务”，点击“新建委托”，填写目标、必要输入、交付物与验收条件。可以立即执行、指定一次性时间，或选择每天、每 7 天、每 30 天的周期。浏览器关闭不影响服务端调度；选择“我本人行动”不会让 Agent 把提醒当成你已经完成行动。

也可点击当前活动侧栏的“关联委托”图标，或在聊天中使用明确形式，例如：

```text
委托任务：把我提供的这段材料整理为三个论点和待验证问题
创建任务：根据当前输入给出一份可核对的摘要
```

随口想法和“也许以后做”不会自动建立执行任务。自然语言目前采用保守的明确指令识别；复杂执行时间与字段建议使用任务表单，避免把识别范围误当成任意自然语言都能正确执行。

当前个人 preset 的可用工具有明确边界。模型配置后可以进行对话与文本产物生成；任意 shell、外部科研服务、邮件或其他第三方操作并未因此获得工具能力或授权。缺材料、缺工具或需额外权限时，任务应保留待补充/权限状态，不能把“准备开始”或缺项说明冒充成果交付。

成果进入“待你验收”后，核对具体版本，再选择“验收此版本”或“要求返修”。验收保存你的原始意见及版本；返修保留同一任务，产生的新成果版本重新等待验收。Agent 自检、沉默和测试夹具都不是你的验收。

需要用自然语言验收时，必须明确任务编号与版本，例如：

```text
任务 实际任务编号 v1 验收通过：这版满足约定条件
任务 实际任务编号 v1 要求返修：请补齐原始出处
```

请将示例中的“实际任务编号”替换为对应真实编号。无法确定版本时，使用看板控件即可。取消周期委托会停止未来执行，保留已提交成果。

## 导入 Kimi、Codex、ChatGPT 资料

把[GPT完整整理指令](templates/chatgpt-material-instructions.md)和[Kimi完整整理指令](templates/kimi-material-instructions.md)分别交给对应平台，让它们按实际可见范围输出文件，再由起居统一处理。每份文件可含多段会话，无需逐段复制或逐条审批；平台不能访问的历史明确列为未覆盖。

在“资料与画像”按真实来源选择文件并预览，可一次选取原话、来源说明和必要助手参考稿，再点“重新预览所选”和“导入所选记录”。核对新增、重复、日期范围、失败和缺失附件；选择改变后重新预览。该步骤保护导入内容与来源，不是每条个人史的批准门槛。

导入保留可追溯来源，起居据本人原话自动整理个人史。平台整理稿始终保留assistant身份，不能伪装成user原话；缺依据的内容标未知或待整理，不自动成为全局画像或已验证的科学结论。相同来源原话精确去重，不同说法保留来源并注明冲突。见[材料说明](MATERIAL_PREPARATION.md)。

| 来源 | 当前适配格式 |
| --- | --- |
| Kimi | 包含 messages/history/items 的 JSON、消息数组，以及以用户/助手标题分段的 Markdown |
| Codex | 原生 rollout JSONL 的可见消息与工具事件；普通 JSON 会话对象；AGENTS.md 和手动 Memory 单独作为资料类型 |
| ChatGPT | 导出 conversations.json 的 mapping 会话结构及分支；手动 Memory 单独作为记忆材料 |

未识别逐消息结构的可读 Markdown 会保留为来源文档，并明确提示没有推断角色或日期。隐藏推理内容不属于可见会话导入。浏览器单个文本文件上限 8 MB；大文件应按来源结构拆分后分别导入。

资料类型与作用域不要混用：

- 历史会话保留为可查原文，默认 `imported`。
- 手动 Memory 与历史会话分开导入；导入本身不会自动变成已确认画像。
- AGENTS / 项目规则使用 `project:项目名` 作用域，仅作为来源材料保存，不执行其中指令，不覆盖系统规则。
- 在画像中明确确认个人全局偏好时使用 `global`；例程专属偏好使用 `routine:A1`、`routine:A2` 或 `routine:A3`，可在作用域建议中选择。“项目规则”类别继续使用 `project:项目名`。待讨论推测不能直接升级为事实。

重复导入按来源指纹去重。移除批次只移除该批新增内容与派生项，不误删导入前已经存在的相同资料。删除账本会阻止已删除内容通过重复导入重新变成有效资料。外部平台未来新增对话不会因一次导入而持续同步。

## 三条成长主线

“成长主线”分别提供博士学位、科研创业、文化事业。每条主线都可以记录目标、能力证据、阶段计划、行动、成果、用户评价、复盘和当前状态，并通过来源或父项建立关系。

阶段计划默认 90 天，可记录约束、近期行动、预期产物和复盘日期。修订保留旧版本，不倒改已经发生的行动与评价，也不会自动授权一批任务。

添加“当前状态”或“用户评价”时，写入你真实的判断并勾选核对。你可以明确记录某条主线当期暂未投入；系统不能从没有记录推断未投入，更不能推断能力下降。至少一条真实成果与评价闭环、三条主线真实状态的核对，分别需要你的实际材料；示例数据和功能测试不代替这些条件。

成长页的周回顾可切换“本周”和“上一完整周”，展示相应时段的持久记录，不额外新增第四项每日推送。后端按自然周归属历史证据；历史记录不能被算成今天的新进展。

## 删除、导出与恢复

“停用此记忆”只停止画像使用，不删除原话。在活动侧栏打开“管理原话”，点击对应原话的垃圾桶“删除这条原话”图标，会说明当前原文、派生项、备份和外部导出的不同范围。

删除前会显示实际影响范围；确认后在检查点中清理目标原话、相关模型派生内容及原生会话副本，后续使用新的原生上下文。其他用户原话、独立更正、委托和评价保留，即使含相同文字。未完成步骤单独显示，并保留重试入口；未知存储布局保持隔离。旧加密备份及独立导出有单独边界，详见 [删除说明](DELETION.md)。

设置页提供 Markdown 可读导出与完整 ZIP。全量导出会取得检查点，并在配置允许时短时停止、随后重启本项目 DSH 宿主；不要在这个短窗口内反复提交。原话有回执后仍以数据库中的持久记录为准。

- 生产数据：`~/.local/share/dsh-personal`
- 本地加密恢复点：`~/.local/share/dsh-personal/backups`
- 最新独立修订/动作账本：`~/.local/share/dsh-personal/recovery-ledger/latest.ledger.enc`
- 备份密钥：`~/.config/dsh-personal/backup.key`，需在独立安全位置保管副本。

完整 CLI、隔离恢复与迁移步骤见 [恢复说明](RECOVERY.md)，模型和通知设置见 [配置说明](CONFIGURATION.md)。从旧备份恢复必须先核对更新的修订/删除账本及外部动作回执，不能直接恢复自动执行。

## 出现问题时

本地后台限额和服务商账户余额分别管理；“设置与运行”显示当前有效限额与实际用量。模型服务商的账户余额、额度和并发限制仍由服务商管理，本应用不能解除；服务商返回余额不足时，原话仍会保存，模型处理需在凭据或账户恢复后继续。

| 看到的状态 | 应怎么做 |
| --- | --- |
| 暂时连不上主机 | 确认 Tailscale 已连接，点“重新连接”或返回前台等待重连；网页无法自行启动被系统停止的 VPN |
| 未确认保存 | 保留草稿，使用原提交的重试入口，不重新复制多份事实 |
| 回答已保存、处理待恢复 | 不必重答；查看模型配置、服务商账户与错误提示，再重试待处理步骤 |
| 原生清理待完成 | 核对删除范围后继续清理；完成前会话保持隔离 |
| 已保存，未重放 | 原话仍在；清理后不自动执行旧请求，如需执行请明确重新发送 |
| 任务待补充或权限窗口结束 | 补齐具体材料/授权范围，再明确继续，不把它视为完成 |
| 仅页面可见 | 尚无已验证的外部通知；不能据此期待锁屏送达 |
| 恢复隔离 | 先完成账本、动作与版本核对，不直接放行旧任务 |

运行情况在“设置与运行”查看，也可在项目目录执行 `bash scripts/control.sh status` 或 `bash scripts/control.sh logs`。长期观察按实际运行时间积累，模拟时钟不能折算为真实运行天数。


## 每日一学的来源与分析


新的学习回复区分“史实与文本依据”“理论分析”“现实类比（假设）”。史实保留出处，分析采用历史唯物主义、辩证唯物主义和政治经济学视角，具体例子说明设定。讲解直接展开知识和推理，取消每课固定的误区、通用边界和预防误读套话；实际影响结论的条件或未知之处在相关句子中准确说明。已保存的表达要求用于后续课程和继续答疑，原课程与旧偏好版本保留。

系统会提前24小时内为下一次有效的学习安排生成课程，分别核对全文与分析段的事实前提。审过的课程先私有保存，到预定时间直接发布正文和发出一次提醒，生成与核对不占用到点后的等待。未发布课程不会提前进入日期归档、个人史或通知。主动点击“打开今天”可提前学习；这样不会在晚间重复提醒。暂停或改时会按最新安排处理，已发布历史课程不变。

如果服务离线或课程仍未通过检查，会记录实际延误；不会用未审稿或“正在准备”的消息冒充准时交付。续聊回复仍需即时核对，会显示真实处理状态。未通过的稿件不会进入聊天；若显示可重试，可在活动信息中重试核对，原话不会重新提交。已发布的学习回复可继续追问，感谢或结束也能自然收尾。核对针对本次提供的材料，仍可能有误判或遗漏；可以直接指出具体句子继续讨论。旧课程保持原样。

完整迁移ZIP与加密备份包含私有备课、审稿及原生会话，用于完整恢复；日常可读JSON、Markdown排除未发布的备课内容。恢复实例保持隔离，缺少完整发布状态时不会仅凭账本回执发布旧草稿。
