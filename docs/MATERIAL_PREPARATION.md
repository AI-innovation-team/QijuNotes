# 让 GPT、Kimi 各自整理文件，再交起居批量处理

材料收集采用**平台分别整理文件 → 起居统一预览、去重 → 起居自动整理成史**。成史不以逐条征求同意为前提；用户可以事后更正、排除或删除。可以把各平台当前能访问的多段材料一次整理进文件，不需要逐段复制给起居。

已准备两份可直接交给平台的整理指令：

- [给 ChatGPT 的整理指令](templates/chatgpt-material-instructions.md)
- [给 Kimi 的整理指令](templates/kimi-material-instructions.md)

两份指令采用同一[批量格式](templates/material-batch-format.md)，要求本人逐字原话、来源说明和模型参考史稿分开。平台能生成下载文件时直接提供JSON文件；不能生成文件时可以输出完整JSON供整体保存，不伪造下载链接。每个平台尽量一份文件，超过8 MB才按完整会话分卷。

## 平台实际能看到什么

整理指令只要求平台依据当前实际可见的会话、用户提供的文件，以及当前工具确实可读且已获授权的资料。它不意味着GPT或Kimi能够自动读取所有历史聊天。无法访问的历史列为未覆盖；只有记忆摘要、没有逐字原话时，保留为未核实线索，不能编造“用户原话”。

起居未实现Kimi/ChatGPT私人历史账号连接器，由平台输出文件后导入起居是当前路径；DeepSeek模型API密钥不提供其他网站的聊天访问权限。不要为材料收集提供密码、API key或公开分享链接。

ChatGPT的原生`conversations.json`已有导出、Kimi普通JSON/Markdown、Codex已选定的rollout JSONL也可以直接交给执行者检查，不必为了统一格式先人工重写。原生ChatGPT mapping分支信息继续保留。普通Kimi与Kimi Code的可见会话范围要区分，不能假定互通；Kimi Code的`/export-md`是终端产品能力，不代表普通Kimi具有同一导出菜单。[Kimi Code官方导出说明](https://www.kimi.com/code/docs/kimi-code-cli/guides/sessions)

平台和账号的导出界面可能不同，已有导出文件可直接使用；平台只整理当前确实可访问的范围，不以“已整理”声称覆盖全部历史。

## 文件应保留什么

| 材料 | 保留方式 |
| --- | --- |
| 本人经历、行动、重要决定、阅读、学习和科研进展的原话 | `role=user`逐字保存，附稳定会话/消息定位和实际可知的原时间。 |
| 原助手回复及本次模型整理 | `role=assistant`，明确区分原上下文与“模型整理／参考史稿”；逐条注明依据。 |
| 可见范围、原标题/链接、未知日期、只有记忆而无原话的线索 | `role=source`，缺少依据的内容标未知或待整理，不伪装成有原话支撑的事实。 |
| 原计划、后续取消、更正或不同说法 | 保留各版本与否定语境，注明尚不一致之处，不擅自裁定。 |
| 假设、技术测试、角色扮演、模型建议、别人经历 | 明确标注，不记作用户已经发生的个人经历。 |

起居需要的是个人史依据，不需要将所有消息等量搬进个人史。先保全重要事实的原话和出处，再组织简明叙述。读过不等于掌握，计划不等于完成，个人科研判断不等于已验证的科学结论；没有依据的成就、心理状态和因果关系不能补写。

原消息时间与事件时间分别保留。原消息有明确时区时使用ISO8601时间；只有日期/月、不知道时区或完全未知时填`created_at: null`，可见线索写进来源说明。不能用整理当天冒充事件发生日。已有私有会话URL可以保存，不创建公开链接；附件只有定位、没有实际文件时保持“缺失附件”。

## 起居如何统一处理

1. 执行者收到GPT/Kimi的文件后，分别按真实平台和“历史会话”类型检查格式、角色、覆盖范围及日期，逐批预览整份文件。已有稳定定位保留，不为合并而重编所有ID。
2. 起居对同一来源、同一定位、同一角色与正文做精确去重；已删来源继续受删除账本约束。相同定位正文发生变化时保留不同记录，跨平台的相似事实也保留各自出处。语义冲突由起居在叙述中标明，不由导入器静默裁决。
3. 网页“资料与画像”可一次全选需要的原话、来源说明及模型参考稿，再点“重新预览所选”和“导入所选记录”；不要求逐条分别提交。两平台文件使用各自来源；当前网页每次接收一个文件，执行者可依次完成批处理。选择变化后必须重新预览。
4. 应用后保留可追溯来源，由起居按史官职责自动整理成史：本人自述的事实、当时的计划、个人判断分别表达，并链接依据。平台给出的assistant史稿保留为参考，不改成user原话；缺少依据的内容标未知或待整理，不阻止其他有依据的内容成史。无需逐条批准，用户可以事后更正或删除。

自动整理需要尊重来源边界，不保证完整捕捉每一件重要事情；成史不自动把历史材料变成全局画像、三主线当前状态或已验证的成长成果。只含模型记忆摘要而没有用户原话的文件保存为线索，缺依据处标未知，不伪造本人经历。用户随时可以修订、排除或沿来源删除，既有删除和恢复约束继续有效。

## 格式兼容性

统一文件使用当前解析器已经支持的`conversations`、会话`id/title`、消息`id/role/content/created_at/attachments`。普通JSON的独立`source_id`输入、自定义metadata或顶层drafts当前不持久化，因此必要出处放在`role=source`正文，参考史稿放在明确标记的`role=assistant`正文。具体字段、未知时间和冲突处理见[格式说明](templates/material-batch-format.md)。[合成批量示例](templates/personal-material-batch-example.json)不代表用户经历，不应用到生产资料库；旧的[小段模板](templates/personal-material-template.md)仅为可选兼容方式，不再作为默认收集要求。


格式适配以 `dsh_personal/records.py` 为准。导入只处理实际提供的材料，不承诺平台能访问其他历史或生成不存在的下载文件。
