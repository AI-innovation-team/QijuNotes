# 删除范围与恢复约束

删除操作先显示实际影响范围与编号；确认时校验计划令牌，记录变化后须重新核对。

## 当前实例中的处理

目标原话、直接归属该消息的附件、相关模型回复、工具结果、摘要、画像与成长派生引用失效。已受这些资料影响的任务旧成果失效并暂停。来源关系由数据库保存，不能仅靠提示词实现删除。

**其他用户原话、独立人工更正、委托要求和本人评价保留，即使含相同文字。** 它们仍可作为后续对话来源。短回答与其他句子文字重合不等于派生关系；不按字符串批量改写用户事实。需要删除另一条独立原文时，应明确选择它的范围。

活动身份与原业务日期保留。清理完成后使用新的原生会话身份，下次主动对话只附带未删除的用户历史及当前有效资料；不重新执行历史委托。已保存但未投递的其他回答标为“已保存，未重放”，避免暗中重复未知外部动作；如需执行，明确重新发送。

导入批次移除也覆盖曾使用该批派生画像的原生会话。仅移除该批新增的资料，之前已存在的重复资料保留。旧版本缺少上下文来源记录时，预览会披露保守纳入的本项目会话范围。

## 原生存储的有限适配

固定 DSH `0.2.1-rc.2` 没有公开的持久会话删除接口。项目使用 `runtime/native_cleanup.py` 在业务排他检查点与原生单写锁内删除**完整、明确归属本实例的会话命名空间**，不改写压缩事件日志内部内容。

适配器校验 UUID、日志 header、V3/V4 代际、路径及已知投影/搜索布局。它移除目标日志及派生缓存，核对不存在后才允许新上下文。遇到活跃写入、未知目录布局、符号/硬链接、未授权继承会话或共享原生附件时拒绝清理，保持相关活动隔离，并提供重试状态。它不是 DSH 上游 API，也不支持任意未来版本。

SQLite 开启 secure_delete，并执行检查点和 VACUUM。若有读者占用，返回“清理待完成”；后台在读者退出后再次尝试，不强杀读者，不提前宣称磁盘旧页已处理。这是当前文件系统的逻辑清理，不承诺物理介质取证不可恢复。

## 导出、旧备份和外部文件

完整导出在原生检查点内核对所有已删会话命名空间，不会把已知残留的原生日志静默重新打包。独立删除账本保存精确消息、任务成果版本、原生会话及来源身份；恢复旧快照时先合并账本、删除旧副本，再重建可读导出并保持实例隔离。

已完成删除后的新消息、新会话和新成果不能因恢复同一删除账本再次被清掉；恢复按精确身份重放，不靠时间戳或文字相似度猜测。活动与任务的稳定来源身份仍可用于新记录。

历史加密备份按保留期退出，恢复必须同时使用较新的删除账本。外部原文件、既有离线导出、用户自行放入 workspace 的独立文件，以及独立原话中的相同文字不在单条删除的自动处理范围内。页面会明确显示这些边界。异机密钥与最新账本的实际恢复仍需另外验收。

## 验证

- `runtime/native_cleanup_probe.py`：固定真实 DSH 进程、压缩日志、重启、旧快照和持久 FTS；其他会话逐字节不变。
- `tests/test_deletion.py`、`tests/test_operations.py`：业务删除、跨画像上下文、独立原话保留、新记录继续、旧/新快照恢复与残留导出拒绝。
- `tests/test_native_cleanup.py`：锁、未知布局、路径链接和权限边界。
