# 公开源码与实例数据

公开仓库是完整的应用源码快照，包含依赖锁文件、测试、文档、基线规格和空白验收账本。真实实例的数据、配置、截图、模型输出和运维记录分别留在实例本地；公开仓库不是这些数据的备份。

从包含私有运维资料的开发仓库整理源码时，可以使用：

```bash
python3 scripts/export-public.py --destination /path/to/new-empty-directory
```

导出器只复制明确允许的已提交源码路径，排除原来的Git历史、`evidence/`、`output/`、实际`progress/`、`docs/USER_INPUTS.md`、运行数据和依赖目录；重新生成项目AGENTS及空白进度/验收模板。它不联网、不读取私有运行配置、不上传文件，也不改变运行服务。

应在导出目录完成回归与内容检查后，再把该目录初始化为Git仓库或合入已有公共发布分支。已有远程提交时保留其历史，不能用开发仓库的整个私有历史覆盖远程。禁止对私有开发仓库执行面向公共远程的 `git push --mirror` 或 `git push --all`。

## 更新流程

1. 在开发仓库提交源码修改，保留实际进度、失败和观察记录。
2. 导出到新的空目录，检查公开文件清单和模板。
3. 在导出目录运行Python回归、账本结构检查，以及本次改动涉及的界面/原生测试。
4. 将审查后的源码提交到公共仓库；只推送选定分支，不上传本地历史、数据和私有证据。

源码上传和生产部署分别记录；文档、测试、安装器整理不要求重启正在服务的实例。实际部署是否变更以实例自己的运行版本与证据为准。
