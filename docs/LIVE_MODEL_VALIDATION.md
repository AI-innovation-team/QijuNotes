# 隔离真实模型验证

scripts/verify-live-model.py 使用实际项目 Worker、原生 DSH 和生产预算网关，业务数据库、原生会话、画像与任务全部位于新建临时目录。不会读取或修改生产原话、画像、日程和委托。生产网关会正常记录这些调用的用量。

先查看不调用模型的计划：

    python3 scripts/verify-live-model.py --phase full

已授权真实调用后先做小样本：

    python3 scripts/verify-live-model.py --run --phase smoke

smoke 为 A3 一轮，最多 3 个上游请求。确认实际供应商、原生回执、回答与 usage 后，再运行完整场景：

    python3 scripts/verify-live-model.py --run --phase full

需分别推进时可用 --phase routines（A2/A3、摘要、更正与画像委托，最低 11 次、默认上限 18）和 --phase learning（A1 首轮加三轮追问，最低 4 次、默认上限 8）。它们是完整场景的独立子集，无需为了补验单项重复运行已取得证据的例程。

--phase focused 只做 A3 语义摘要与更正后的续聊，硬上限2调用。前三条用户历史在临时数据库中预置并按新generation上下文提供，不能把这个模式声称为前三轮也重新调用了模型。摘要输入snapshot、模型原始JSON和失败也留证，来源校验失败时停测而不放宽校验。

完整计划最低 15 请求：三例程各首轮加三次追问，共 12 原生轮；A2/A3 在第三次追问前各生成一次实际语义摘要；最后一次隔离委托核对新画像与未经确认的假设。完整场景总上限默认 24、允许参数最大 25；每轮最多 3 请求，包含原生工具续轮。请求输出均被本地计数代理限制在最多 1200 tokens，生产网关仍施加其自身限制。达到限额或出错就停下，不自动扩大预算或重复调用。

如初轮 A1 被1200验证上限截断，先保留失败报告，再在明确扩大该单轮测试上限的授权下使用 --learning-initial-limit 2048。这个参数只改变 A1.initial，后续追问和摘要仍不超过1200，生产默认上限也不变。脚本识别 finish_reason=length，并检查初轮三个给定来源链接是否都出现；缺链或截断停止，链接存在本身仍不证明内容准确。

A3 原样本“昨晚00:30”在首次实际 smoke 中暴露日期与6.5小时计算矛盾，原报告保留。当前正式样本明确为2026-10-22凌晨00:30至同日07:00；摘要前再更正虚构起床时间为07:40、质量为4分，并修订虚构画像排期窗口。后续回答与独立委托用于实际检查更正及当前画像。所有人物与经历都明确标为合成开发样本，不写成真实用户经历，不作用户接受。

脚本只在进程中读取本项目的内部 gateway-key，不打印，不写入测试报告，不读取供应商 key 文件。生产配置仅保留非秘密模型字段；生产 SQLite 仅只读查询 usage / usage_details 的数值及回执白名单。原生宿主通过随机端口的本地计数代理调用 18782；原始 Worker.semantic_summary 仅在测试程序内部重定向 HTTP 传输，算法、解析、来源检查及提交保持原路径，也受同一限额控制。运行后停止隔离进程组并删除临时目录。

默认报告写入 evidence/P4/live-model-PHASE-UTC时间.json，权限 0600。已有报告不覆盖，可用 --report 指定新文件名。报告包含合成用户输入、真实模型全文、原生事件、业务状态、实际模型摘要、人工更正、当前画像任务、调用次数、输出限额及原始数值 usage。每请求读取前后账本 ID 差集，只在唯一候选时标为请求窗口对应；并发生产调用导致多个候选时明确标为歧义，不将同期生产总用量冒充测试消耗。响应里的 usage 属于该请求本身，推理子项不再次累加 total。

脚本不自动修改验收账本。成功状态为 ENGINEERING_SCENARIOS_RECORDED_REVIEW_REQUIRED：说明场景实际执行并留证，不代表学习出处正确、内容语境合格或用户接受。必须逐段核对 A1 三类内容与原始出处，A2 不强制跳维度或虚构进展，三例程第三轮仍承接上下文，A3 使用更正值，实际委托使用新画像而不把未知偏好说成事实。供应商 usage 的推理包含关系仍须与官方文档一起判断；并发预算、重启预留与超额保护由既有独立故障测试覆盖，不能仅凭一次真实调用宣称全部证明。

无需供应商的脚本检查：

    python3 -m unittest discover -s tests -p test_verify_live_model.py -v

这些测试验证默认不读取配置/认证、不启动实例，并发调用硬限额、上游请求前的限额拒绝、输出限额与报告不含内部认证。它们不替代真实调用。
