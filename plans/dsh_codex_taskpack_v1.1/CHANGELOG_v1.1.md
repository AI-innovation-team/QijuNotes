# 1.1变更与开发范围确认

日期：2026-10-22。来源：用户对1.0整合稿的明确反馈，并授权准备任务指令。

## 本次三项修订

| 用户要求 | 1.1规则 | 主要位置与验收 |
| --- | --- | --- |
| 不建议自动降频，除非用户明确表态，每日唤醒 | A1–A3每日触发；频率/暂停只由明确用户输入改变，单次跳过不影响明日 | SPEC 1.1、3.4、4、12；T04 |
| 提供填补前几日空缺的通道 | 近7天初始视图，可选任意历史日；已有续答、缺失按原日期补建，保留实际补填时间 | SPEC 2.4、4.2–4.3；T26 |
| 每个定时任务仍为聊天交互，可不断深入 | 三例程基础记录完成后仍可多轮深入；默认澄清次数不是对话上限 | SPEC 3.1–3.5、4.1；T05 |

## 已撤销的旧规则

1.0的每天→周一三五→周一自动阶梯、低参与标签驱动调度、14天统计窗口、连续3次阈值及已看未答24小时降频判断均不再适用。旧实现若已存在，须移除或禁用它们对实际日程的作用，并用T04证明不会复发。它们不作为隐藏可选开关交付。

用户明确说“改成每周三次”“暂停到某日”仍应直接执行指定变更。这与系统从沉默推断调整意愿不同。

## 保留的范围

学习三项内容、三维反思、睡眠记录、完整原文、定向摘要、用户纠错、三平台导入、三条成长线、明确委托与人类验收、多端使用、Linux长期运行、预算、备份和迁移继续有效。旧需求映射中的“A3打卡降频”以“A3每日打卡与显式调频”替换。

26条验收包含原25条的修订及新增T26历史补填。用户对文档范围的确认不等于系统部署通过，任务包初始没有任何实际运行PASS。

## 本包不预设的事实

目标主机发行版、已安装DSH版本、当前插件接口、手机系统、通知通道、凭据和异机备份位置，由执行者检查或在确实缺少时一次获取。产品默认JSON不是DSH可直接导入的原生配置。
